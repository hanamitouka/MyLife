# Mylife 时间管理软件 · 产品需求文档（PRD 草稿）

> 版本：v0.1 · 日期：2026-09-25 · 状态：草稿（待评审）
> 对应代码库：`/mnt/ddisk/Datas/mylife`

---

## 1. 产品定位

**Mylife** 是一款面向个人用户的时间管理软件，核心围绕「时间轴 + 待办清单 + 目标追踪」三大模块展开，帮助用户：

- 通过时间轴直观规划每日任务；
- 用任务卡牌快速排期；
- 管理无截止日期的待办、习惯打卡和有截止日期的 DDL；
- 对长期目标进行拆分、记录和推进，尤其降低目标启动困难人群的使用门槛；
- 通过个人成就界面获得反馈，增强执行动力。

---

## 2. 核心模块与架构关系

```text
Mylife 主界面 / Dashboard
├── 开屏时间轴
│   ├── 今日时间轴
│   ├── 前后多日时间轴
│   └── 任务卡牌 / 待排期卡牌池
├── 便捷待办打卡
│   ├── 习惯打卡
│   ├── 待办清单
│   └── DDL 提醒
└── 当前目标
    ├── 目标进度
    ├── 子目标
    └── 目标日志

核心对象联动关系：
待办 <--> 任务卡牌 <--> 时间轴
目标 <--> 子目标 / DDL <--> 任务卡牌 / 待办
习惯打卡 / 任务完成 / 目标推进 --> 个人成就统计
```

---

## 3. 名词定义

| 名词 | 说明 |
|---|---|
| 任务卡牌 | 用户创建的可拖拽任务卡片，包含任务类型、计划时间等信息，可放入时间轴完成规划 |
| 活动卡牌 | 与目标推进相关的卡牌，可用于记录目标相关的活动时间，是否与任务卡牌同模型待确认 |
| 待办 | 没有明确截止日期，但需要完成的事项 |
| DDL | 带有明确截止日期的任务 |
| 子 DDL | 某个大 DDL 下的阶段性截止任务 |
| 目标日志 | 针对目标记录的进度、感想，带时间戳 |
| 热度图 | 按日期展示任务/习惯/目标执行活跃度的统计图 |
| P 人友好 | 面向目标启动困难、需要低门槛推进机制的用户 |

## 4. 功能需求详情

### 4.1 时间轴模块

| 编号 | 需求名称 | 详细说明 / 规则 | 优先级 |
|---|---|---|---|
| TL-01 | 默认展示今日时间轴 | 打开软件后默认显示今天的时间轴，定位到当前时间附近 | P0 |
| TL-02 | 今日高亮 | 今日日期、今日时间轴需要高亮显示，与其他日期明显区分 | P0 |
| TL-03 | 电脑端多日时间轴 | 电脑端可同时查看今天前后多日时间轴，今日高亮 | P0 |
| TL-04 | 手机端日期切换 | 手机端默认展示今日，左右滑动可平滑切换到前后日期 | P0 |
| TL-05 | 任务卡牌附着 | 已规划到时间轴的卡牌显示在对应时间位置上 | P0 |
| TL-06 | 待排期卡牌区 | 时间轴旁边或下方提供"等待拖拽的任务卡牌"区域 | P0 |
| TL-07 | 当前时间指示线 | 时间轴中显示当前时间线，便于判断任务先后 | P1 |
| TL-08 | 时间冲突提示 | 同一时间段出现多个任务卡牌时，给出视觉提示或折叠展示 | P1 |
| TL-09 | 跨日任务显示 | 若任务跨天，支持在多日时间轴上连续显示 | P2 |

### 4.2 任务卡牌模块

| 编号 | 需求名称 | 详细说明 / 规则 | 优先级 |
|---|---|---|---|
| TC-01 | 创建任务卡牌 | 用户可创建卡牌，支持填写名称、任务类型、计划时间、时长等 | P0 |
| TC-02 | 自动带出类型与时间 | 卡牌默认记录任务类型、创建时间/计划时间，减少用户填写成本 | P0 |
| TC-03 | 拖拽排期 | 将卡牌从卡牌池拖到时间轴即完成规划，可再次拖动调整时间 | P0 |
| TC-04 | 卡牌状态流转 | 支持待排期、已排期、进行中、已完成、已逾期、已取消等状态 | P0 |
| TC-05 | 编辑 / 复制 / 删除 | 已创建卡牌支持编辑、复制和删除 | P0 |
| TC-06 | 与待办清单联动 | 待办可转为任务卡牌；卡牌完成后可回写对应待办状态 | P1 |
| TC-07 | 与目标追踪联动 | 目标可生成任务卡牌或活动卡牌，卡牌完成后可推进目标进度 | P1 |

### 4.3 待办清单模块

#### 4.3.1 习惯管理

| 编号 | 需求名称 | 详细说明 / 规则 | 优先级 |
|---|---|---|---|
| HB-01 | 创建习惯 | 用户可创建习惯，设置名称、图标、周期、提醒时间等 | P0 |
| HB-02 | 习惯打卡 | 每日可对习惯进行打卡，完成状态可记录 | P0 |
| HB-03 | 强制性分类 | 习惯分为强制性、半强制性、非强制性三类，不同类型对应不同提醒和处理规则 | P0 |
| HB-04 | 习惯统计 | 展示连续打卡天数、完成率、未完成记录 | P1 |

> 强制/半强制/非强制的具体规则需要进一步确认，例如：
> - 强制性：到期必须打卡，未打卡会持续提醒并中断连续记录。
> - 半强制性：允许补卡或延迟，但不计入中断。
> - 非强制性：自由打卡，不影响统计连续性。

#### 4.3.2 待办管理

| 编号 | 需求名称 | 详细说明 / 规则 | 优先级 |
|---|---|---|---|
| TD-01 | 新建无 DDL 待办 | 用户可快速添加没有截止日期的待办事项 | P0 |
| TD-02 | 默认排序规则 | 默认按添加时间顺序排列 | P0 |
| TD-03 | 优先级设置 | 用户可自由设置优先级或手动调整上下顺序、置顶 | P0 |
| TD-04 | 完成与恢复 | 待办可勾选完成，也可恢复为未完成 | P0 |
| TD-05 | 转为任务卡牌 | 待办可一键转为任务卡牌，排入时间轴 | P1 |

#### 4.3.3 DDL 管理

| 编号 | 需求名称 | 详细说明 / 规则 | 优先级 |
|---|---|---|---|
| DL-01 | 创建带截止日期任务 | 创建任务时可添加明确的截止日期，进入 DDL 管理 | P0 |
| DL-02 | 剩余时间提醒 | 展示距离截止日期还有多久，例如"还有 3 天 2 小时" | P0 |
| DL-03 | 催 DDL 时间设置 | 用户可设置提前催办时间，如提前 1 天、提前 2 小时提醒 | P0 |
| DL-04 | 逾期展示 | 已逾期任务明显标红，并提示已逾期多长时间 | P1 |
| DL-05 | 子 DDL 支持 | 一个大的 DDL 可拆分为多个子 DDL，实现阶段截止管理 | P1 |

### 4.4 目标追踪模块

| 编号 | 需求名称 | 详细说明 / 规则 | 优先级 |
|---|---|---|---|
| GT-01 | 添加目标 | 可添加目标，支持名称、描述、开始/截止时间、状态等 | P0 |
| GT-02 | 目标分解 | 目标可拆解为多个子目标，支持层级结构 | P0 |
| GT-03 | 目标日志 | 用户可随时记录目标完成进度和感想，每条日志带时间戳 | P0 |
| GT-04 | 目标活动卡牌 | 可选择是否为目标生成活动卡牌，并放入时间轴 | P1 |
| GT-05 | 目标相关待办 | 可选择是否为目标生成相关待办，同步到待办清单 | P1 |
| GT-06 | 与 DDL 联动 | 目标支持添加子 DDL，例如大作业总 DDL 下设置某模块完成日期 | P1 |
| GT-07 | 进度计算 | 根据子目标完成情况或相关待办完成率计算目标整体进度 | P0 |
| GT-08 | 低启动成本设计 | 面向 P 人，展示"下一步最小行动"或首条未完成子目标，降低开始难度 | P2 |

### 4.5 主界面 Dashboard

| 编号 | 需求名称 | 详细说明 / 规则 | 优先级 |
|---|---|---|---|

## 5. 模块联动规则汇总

| 关联对象 | 联动规则 |
|---|---|
| 待办 → 任务卡牌 | 待办可转为卡牌，拖入时间轴进行排期 |
| 任务卡牌 → 待办 | 任务卡牌完成时，可同步完成对应待办 |
| 目标 → 任务卡牌 | 目标可生成相关任务卡牌或活动卡牌 |
| 目标 → 待办 | 目标可生成相关待办，进入待办清单 |
| 目标 → DDL | 目标可添加子 DDL，形成阶段截止任务 |
| 习惯打卡 → 热度图 | 每日打卡记录计入个人成就热度图 |
| 任务卡牌 → 个人成就 | 完成的任务卡牌按类型、时间进入统计 |
| DDL → 主界面 | 临近截止的 DDL 在便捷待办打卡区域高亮提醒 |

## 6. 核心数据实体建议

| 数据实体 | 说明 |
|---|---|
| 用户 User | 账号、偏好设置 |
| 任务卡牌 TaskCard | 名称、类型、开始时间、时长、状态、关联待办/目标 |
| 待办 Todo | 名称、优先级、状态、创建时间、完成时间 |
| 习惯 Habit | 名称、周期、强制性分类、提醒时间 |
| 打卡记录 HabitCheckIn | 习惯 ID、日期、是否完成、打卡时间 |
| DDL 任务 DdlTask | 名称、截止时间、催办时间、父 DDL、状态 |
| 目标 Goal | 名称、描述、开始/截止日期、状态、总进度 |
| 子目标 SubGoal | 目标 ID、父级 ID、名称、权重、状态、截止时间 |
| 目标日志 GoalLog | 目标 ID、内容、时间戳 |
| 活动卡牌 ActivityCard | 名称、类型、开始时间、时长、关联目标 |
| 每日统计 StatsDaily | 日期、打卡数、完成任务数、目标推进记录 |

## 7. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-01 | 多端适配：PC 端和移动端需要良好的响应式体验 |
| NFR-02 | 时间轴拖拽和左右滑动需要流畅，移动端应避免明显卡顿 |
| NFR-03 | 提醒通知可靠，特别是 DDL 催办和习惯打卡提醒 |
| NFR-04 | 支持账号同步和本地离线缓存，防止数据丢失 |
| NFR-05 | 提供数据导出与备份能力 |
| NFR-06 | 个人数据需保证私密性 |
| NFR-07 | 界面和信息密度适合个人用户，避免过于复杂的设置 |

## 8. 建议迭代优先级

### P0：核心可用版本
- 今日时间轴 + 任务卡牌拖拽
- 无 DDL 待办 + 优先级排序
- DDL 倒计时与催办提醒
- 基础习惯打卡
- 目标添加、子目标分解、目标日志
- 主界面三区布局

### P1：增强联动与统计
- 待办/卡牌/目标/DDL 互相联动
- 子 DDL 管理
- 目标活动卡牌与相关待办
- 个人成就热度图与统计

### P2：进一步优化
- 高级提醒策略
- 跨日任务展示优化
- 周/月/年报告
- 低启动成本的智能建议

## 9. 待确认问题

1. 习惯的"强制性 / 半强制性 / 非强制性"具体有什么不同？未完成时是否影响连续记录？
2. 时间轴的时间刻度是多少？是否支持 15 分钟、30 分钟等自定义粒度？
3. 任务卡牌是否必须设置开始时间和结束时间，还是可以只设置开始时间？
4. 电脑端"前后多日时间轴"具体是 3 日、5 日、周视图还是可自由切换？
5. 目标生成的"活动卡牌"与普通"任务卡牌"是否是同一个数据模型？
6. 目标整体进度如何计算？是按子目标权重，还是按任务/卡牌完成数量？
7. 子 DDL 完成后是否自动更新主 DDL 的进度？
8. 催 DDL 时间是单次提醒，还是可以设置多次提醒？
9. 个人成就热度图按什么口径统计？例如打卡次数、完成任务数还是投入时长？
10. 是否需要账号体系与多设备同步？
